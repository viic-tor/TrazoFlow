01

Todo lo que puedes realizar con la Skill de Trazo

[CAPABILITIES_MATRIX]

La skill de Trazo (SKILL.md / AGENTS.md) convierte a tu agente de IA (Antigravity, Claude Code, Codex o Pi) en un ingeniero de documentación visual disciplinado. En lugar de inventar cajas o producir SVGs rotos con texto encimado, el agente ejecuta un flujo verificable de extremo a extremo:

01. Diagramar código real AUDITABLE

El agente lee primero tu repositorio y dibuja únicamente lo que existe en el código. Cada componente puede llevar "source": "ruta/archivo.ts:linea" para auditarlo al pasar el cursor.

02. Cuatro vistas técnicas SEMÁNTICO

Genera diagramas de Arquitectura (cajas y grupos), Workflow (pasos, decisiones y carriles), ERD (tablas, columnas y FKs con pata de gallo) y Secuencia (mensajes y fragmentos alt/opt/loop).

03. Validación estricta AUTO-FIX

Con trazo check detecta errores de esquema, referencias rotas, IDs duplicados, ciclos en grupos y tipos incompatibles en FKs, ofreciendo ruta JSON exacta y sugerencias tipo "did you mean".

04. Revisión geométrica LINTER

Al compilar con trazo make, analiza colisiones de nodos, desbordamiento de texto, solapamiento de etiquetas y aristas que cruzan cajas, emitiendo avisos accionables en stderr.

05. HTML interactivo offline ZERO-DEPS

Produce un solo archivo .html con Zoom, Paneo, enfoque por teclado, resaltado de conexiones vecinas, tooltips de notas/fuentes, pantalla completa y cambio de tema Claro/Oscuro en vivo.

06. Exportación vectorial/PNG DOCS READY

Desde cualquier diagrama HTML generado puedes descargar SVG autocontenido (con fuentes y colores del tema actual) o PNG en resolución 2x (HiDPI) sin marca de agua para pegar en READMEs o slides.

07. Diagramas versionables DOCS-AS-CODE

Guarda la fuente semántica en docs/diagrams/*.json dentro de Git. Como el JSON es minimalista y legible, puedes ver diffs limpios en PRs y regenerar el HTML cuando el código cambie.

08. Pipelines UNIX y CI/CD AUTOMATION

Soporta lectura desde stdin (-), salida a stdout (-o -), salida estructurada --json y códigos de salida estándar (0, 1, 2, 3) para validar diagramas en CI.

09. Uso como librería ESM NODE API

Además de la CLI, puedes importar check() y make() en tus propios scripts o herramientas en Node.js >= 22 para generar diagramas HTML programáticamente.

02

Los 4 Tipos de Diagrama (Esquemas, Reglas y Ejemplos)

[DIAGRAM_SPECS]

Selecciona un tipo de diagrama para inspeccionar sus elementos, sintaxis abreviada, reglas de validación, límites recomendados y un JSON completo listo para ejecutar.

ARCHITECTURE — Componentes, sistemas, almacenes y enlaces default: direction right

Ideal para mapas de microservicios, infraestructura, arquitectura de módulos o flujo de datos de alto nivel. Permite agrupar nodos y anidar grupos en cajas contenedoras.

┌──────────┐ HTTPS ┌─────────────┐ ┌─── BACKEND ────────────────────────────────┐ │ Customer │ ────────► │ API Gateway │ ─────► │ [Orders Service] ──► (Orders DB) │ └──────────┘ └─────────────┘ │ │ ~~~~~~~~► [Order Events (Queue)] │ └─────────┼──────────────────────────────────┘ ▼ (async) ┌──────────────────┐ │ Print Lab Worker │ └──────────────────┘

Tipos de Nodo (kind)

  • client · user · gateway
  • service (por defecto) · function
  • database · cache · queue · storage
  • external (proveedores o APIs de terceros)

Sintaxis de Aristas (edges)

  • "a -> b: etiqueta" — llamada síncrona (sync)
  • "a ~> b: etiqueta" — evento/cola/job asíncrono (async)
  • Objeto completo: { from, to, label?, style?: "sync"|"async"|"data" }

Reglas y Límites Estrictos

  • direction: "right" (defecto) o "down".
  • Los id son únicos entre todos los nodes y groups (solo letras, dígitos, _ . -; empieza con letra o _).
  • Cada nodo o subgrupo pertenece a un solo grupo; prohibidos ciclos de contención.
  • Las aristas pueden apuntar tanto a un node como a un group existente.
  • Soporta note y source: "ruta/archivo.ts:linea" en hover.
  • Aviso límite: más de 60 nodos dispara alerta → dividir por área.

WORKFLOW — Pasos, decisiones, reintentos y carriles (swimlanes) default: down (right con lanes)

Diseñado para procesos de negocio, pipelines CI/CD, flujos de aprobación, máquinas de estado operativas o procedimientos con responsables separados por lanes.

LANE: Requester │ (Start) ──► [Submit request] ───────────────────────────────► (End) ──────────────────┼───────────────────────────────────────────────────────────────▲──── LANE: Procurement │ └──► <Within budget?> ──[over]──► [Reject] ─┘ │ └──[in budget]──► [[Onboarding]] ──► [Order] ──────────────────┼──────────────────────────────────────────────────────────────────┼── LANE: Finance │ (async invoice) ◄~~~┘ │ [Send payment] ◄──[retry]── <Paid?>

Tipos de Paso (kind)

  • start — inicio (etiqueta por defecto: "Start")
  • end — fin (etiqueta por defecto: "End")
  • task — acción/paso normal (por defecto)
  • decision — rombo condicional con bifurcaciones
  • wait — espera de evento, webhook o entrega
  • subprocess — subproceso externo/encapsulado

Aristas (edges)

  • "a -> b: etiqueta" — siguiente paso (sync)
  • "a ~> b: etiqueta" — entrega asíncrona (async)

Reglas y Límites Estrictos

  • start NO puede tener aristas entrantes; end NO puede tener salientes.
  • Todo decision exige al menos 2 aristas salientes (etiqueta cada respuesta).
  • Si usas lanes, cada paso debe pertenecer exactamente a 1 lane y el flujo siempre corre hacia la derecha (right).
  • Soporta note y source por paso.
  • Aviso límite: más de 40 pasos dispara alerta → extraer a subprocesos.

ERD — Tablas, columnas tipadas y claves foráneas a nivel columna CROW'S FOOT AUTOMÁTICO

Ventaja clave de Trazo: las claves foráneas apuntan directamente a la columna destino, no solo a la tabla, y las terminaciones de cardinalidad (pata de gallo / opcionalidad) se deducen automáticamente de unique y null.

┌──────────────────────┐ ┌──────────────────────┐ │ customers │ │ orders │ ├──────────────────────┤ ├──────────────────────┤ │ PK id uuid │◄──┐ │ PK id uuid │◄──┐ │ UQ email text │ └────○┼ FK customer_id uuid │ │ (unique = 1:1) │ full_name text │ │ status text │ │ ┌────────────────────┐ └──────────────────────┘ └──────────────────────┘ └──│ payments │ │ PK id uuid │ │ FK UQ order_id uuid│ └────────────────────┘

Definición de Columnas (2 Formas)

  • Forma corta (string): "nombre tipo [pk] [fk tabla.col] [unique] [null]"
  • Ejemplos: "id uuid pk", "order_id uuid fk orders.id unique", "price numeric(10, 2)", "bio text null".
  • Las marcas pueden ir en cualquier orden y mayúsculas/minúsculas.
  • Forma objeto (para notas): { name, type, pk?, unique?, nullable?, fk?, note? }.

Deducción de Cardinalidad

  • Sin unique → relación muchos (N) hacia el padre.
  • Con unique → relación a lo sumo uno (1:1).
  • Con null → el padre es opcional (0..).

Reglas y Límites Estrictos

  • Los id de tabla aceptan puntos para esquemas: ej. public.users.
  • Sin campo source: el esquema ERD no usa source (solo note).
  • fk apunta a una sola columna existente (no soporta llaves compuestas).
  • Emite warning si la columna destino de una FK no es pk/unique o si los tipos difieren.
  • Emite warning si una tabla no tiene pk.
  • Aviso límite: más de 40 tablas o 30 columnas por tabla.

SEQUENCE — Participantes, mensajes temporales y bloques de control ALT / OPT / LOOP

Perfecto para protocolos de autenticación (OAuth/JWT), flujos HTTP/webhooks, pagos, sagas distribuidas y trazas de ejecución en orden cronológico.

[Shopper] [Orders API] [Inventory DB] [PSP External] │ │ │ │ │── Place order ─►│ │ │ │ │── Reserve items ─►│ │ │ ┌─ ALT [all items in stock] ────────────┤ │ │◄── Reservation ───│ │ │ │────────────── Charge card ───────────►│ │ │ ┌─ LOOP [until settled, max 3] ─────┤ │ │ │◄──── Pending ─────────────────────│ │ │ └───────────────────────────────────┘ │◄── 201 Created ─│ │

Participantes (kind) y Mensajes

  • actor · service (defecto) · database · queue · external
  • "a -> b: texto" — llamada síncrona (sync); "a -> a" es auto-llamada.
  • "a ~> b: texto" — mensaje asíncrono (async).
  • "a --> b: texto" — respuesta (reply).
  • Objeto completo: { from, to, label?, style?: "sync"|"async"|"reply" }.

Notas y Fragmentos

  • { "note": "...", "over": "id" } o "over": ["id1", "id2"]
  • { "opt": { "when": "...", "messages": [...] } }
  • { "loop": { "when": "...", "messages": [...] } }
  • { "alt": [{ "when": "...", "messages": [...] }, ...] } (mín. 2 ramas)

Reglas y Límites Estrictos

  • Una respuesta a sí mismo (a --> a) es error.
  • Una respuesta sin una solicitud previa correspondiente emite warning.
  • Los fragmentos opt, loop y alt se pueden anidar hasta un máximo de 2 niveles.
  • Soporta note y source en participantes.
  • Aviso límite: más de 8 participantes o 60 mensajes.
JSON // trazo example sequence 
{
  "type": "sequence",
  "title": "Checkout",
  "description": "How a cart becomes a paid order.",
  "participants": [
    { "id": "shopper", "label": "Shopper", "kind": "actor" },
    { "id": "web", "label": "Storefront" },
    { "id": "orders", "label": "Orders API" },
    { "id": "stock", "label": "Inventory", "kind": "database" },
    { "id": "psp", "label": "Payment provider", "kind": "external" },
    { "id": "events", "label": "Order events", "kind": "queue" }
  ],
  "messages": [
    "shopper -> web: Place order",
    "web -> orders: POST /orders",
    "orders -> stock: Reserve items",
    {
      "alt": [
        {
          "when": "all items in stock",
          "messages": [
            "stock --> orders: Reservation id",
            "orders -> psp: Charge card",
            {
              "loop": {
                "when": "until settled, max 3",
                "messages": ["psp --> orders: Pending", "orders -> orders: Wait with backoff"]
              }
            },
            "psp --> orders: Captured",
            "orders ~> events: order.paid"
          ]
        },
        {
          "when": "missing items",
          "messages": ["stock --> orders: Out of stock", "orders --> web: 409 Conflict"]
        }
      ]
    },
    { "note": "Reservations expire after 15 minutes.", "over": ["orders", "stock"] },
    "orders --> web: 201 Created",
    "web --> shopper: Order confirmation"
  ]
}

Las 8 Reglas del Protocolo de la Skill (SKILL.md)

[AGENT_CONTRACT]

Esto es exactamente lo que la skill trazo instruye a tu agente de IA cada vez que se activa. Conocer estas 8 reglas te permite auditar su comportamiento y sacarle el máximo provecho:

01

Elegir tipo exacto

Clasifica la petición en uno de los 4 modelos: architecture (componentes y enlaces), workflow (pasos y decisiones), erd (tablas y FKs) o sequence (mensajes entre actores).

02

Cero alucinaciones

Si describe código, lee el código primero y dibuja solo lo encontrado. Mantiene 1 solo nivel de detalle (servicios O módulos, nunca mezclados). Si hay ambigüedad, pregunta al usuario.

03

Partir del ejemplo oficial

Ejecuta trazo example <type> > diagram.json y lo edita en el proyecto actual (en repositorios, bajo docs/diagrams/). Solo consulta trazo schema <type> si necesita un campo extra.

04

Solo semántica + trazabilidad

Prohibido escribir posiciones, tamaños o colores. Usa label, kind, note y source: "path/file.ts:line" para verificar cada pieza (excepto erd, que no lleva source).

05

Validar antes de compilar

Ejecuta siempre trazo check <file> y después trazo make <file> -o <ruta>.html, informando al usuario la ruta final del archivo HTML generado.

06

Edición quirúrgica de errores

Si check reporta errores, corrige cada ruta listada, aplica sugerencias "did you mean" y revalida. Edita el archivo en el sitio (in place) en vez de reescribirlo entero.

07

Gestión inteligente de warnings

Acorta texto ante text-overflow/label-overlap; cambia direction o agrupa ante edge-through-node/node-overlap. Ignora outside-canvas y outside-group (son bugs del motor).

08

Dividir sistemas grandes

Al superar 60 nodos (o los topes de cada tipo), la herramienta advierte y el agente debe dividir la vista en varios diagramas focalizados por dominio.

Guía de Instalación Completa: Linux y Windows

[DEPLOY // OS_SETUP]
[PRERREQUISITO OBLIGATORIO EN AMBOS SISTEMAS]
Node.js 22 o superior (engines.node: ">=22"). Trazo no instala la skill de agentes automáticamente al instalar el paquete npm: son dos pasos (1. Instalar CLI @heidenber/trazo + 2. Copiar SKILL.md o AGENTS.md en el directorio de tu agente).
LINUX // INSTALACIÓN PASO A PASO RECOMENDADO: NVM / FNM

Paso 1 — Verificar o instalar Node.js >= 22

Comprueba tu versión actual. Usar nvm evita errores de permisos EACCES al instalar paquetes globales (y evita usar sudo npm i -g):

BASH // Verificar Node o instalar v22 LTS con nvm 
# 1. Comprobar versión actual (debe ser v22.x o superior)
node -v && npm -v

# 2. Si no tienes Node >= 22, instala nvm (recomendado en Linux):
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
source ~/.bashrc   # o ~/.zshrc si usas Zsh

# 3. Instalar y activar Node 22 LTS (o v24):
nvm install 22
nvm use 22
nvm alias default 22
node -v

Paso 2 — Instalar la CLI de Trazo globalmente

BASH // Instalación global via npm 
npm i -g @heidenber/trazo

# Verificar binario y versión instalada (debe ser >= 0.1.4)
which trazo
trazo --version

Paso 3 — Instalar la Skill para tu Agente de IA

Copia SKILL.md o añade AGENTS.md en la ruta correspondiente al agente que utilices:

BASH // Instalar skill en Antigravity, Claude Code, Pi y Codex 
SK="$(npm root -g)/@heidenber/trazo/skill"

# Antigravity / Gemini CLI
mkdir -p ~/.gemini/config/skills/trazo && cp "$SK/SKILL.md" ~/.gemini/config/skills/trazo/

# Claude Code
mkdir -p ~/.claude/skills/trazo && cp "$SK/SKILL.md" ~/.claude/skills/trazo/

# Pi Agent
mkdir -p ~/.pi/agent/skills/trazo && cp "$SK/SKILL.md" ~/.pi/agent/skills/trazo/

# Codex (NO ejecutar dos veces sin limpiar el bloque previo)
mkdir -p ~/.codex && cat "$SK/AGENTS.md" >> ~/.codex/AGENTS.md

Paso 4 — Prueba de humo (Smoke Test)

BASH // Generar y abrir tu primer diagrama de prueba 
trazo example architecture > demo.json
trazo check demo.json
trazo make demo.json -o demo.html --theme dark

# Abrir en el navegador por defecto en Linux:
xdg-open demo.html
[TROUBLESHOOTING LINUX — PUNTOS CRÍTICOS A REVISAR]
  • Error EACCES: permission denied al hacer npm i -g: ocurre con el Node del sistema (apt/dnf). NO uses sudo; usa nvm o redirige el prefijo de npm: mkdir -p ~/.npm-global && npm config set prefix '~/.npm-global' y agrega export PATH="$HOME/.npm-global/bin:$PATH" a tu ~/.bashrc / ~/.zshrc.
  • trazo: command not found tras cambiar de versión en nvm: los paquetes globales en nvm son por versión de Node. Si cambias de Node 22 a 24, reinstala npm i -g @heidenber/trazo en esa versión.
  • WSL (Windows Subsystem for Linux): para abrir el HTML generado en el navegador de Windows desde WSL, usa explorer.exe demo.html o wslview demo.html.
  • Actualizar la skill en Codex: antes de volver a concatenar AGENTS.md, elimina todo lo que esté entre <!-- trazo:start --> y <!-- trazo:end --> en ~/.codex/AGENTS.md para evitar duplicados.
WINDOWS // INSTALACIÓN PASO A PASO POWERSHELL / WINGET

Paso 1 — Verificar o instalar Node.js >= 22

Abre Windows Terminal (PowerShell). Puedes instalar Node 22 LTS vía winget, nvm-windows o el instalador oficial .msi desde nodejs.org:

POWERSHELL // Comprobar versión o instalar Node.js LTS con winget 
# 1. Comprobar si ya tienes Node >= 22
node -v
npm -v

# 2. Si no lo tienes, instalar Node.js LTS mediante winget:
winget install --id OpenJS.NodeJS.LTS -e --source winget

Capacidades del Visor HTML Generado y Atajos

[INTERACTIVE_HTML_ENGINE]

Cada archivo .html generado por trazo make es una aplicación visual autónoma: incrusta el SVG, la tipografía Inter, los íconos Lucide y el motor interactivo en un único fichero sin peticiones externas ni servidor local.

Controles e Interacciones del Visor
  • Paneo (Pan): clic izquierdo y arrastrar (ratón o 1 dedo en pantalla táctil).
  • Zoom fluido (0.25x a 8x): rueda del ratón sobre el puntero, pellizco de 2 dedos (pinch-to-zoom) o botones de la barra.
  • Inspección de vecinos (Focus/Hover): al pasar el cursor, tocar o enfocar un nodo con Tab, el resto del diagrama se atenúa (.t-dim) y se iluminan únicamente el nodo y sus aristas/nodos conectados (.t-near).
  • Tooltips con trazabilidad: muestra el texto de note y la referencia de archivo source ("archivo.ts:linea") con soporte ARIA accesible.
  • Tema en vivo: botón para alternar entre light y dark sin regenerar el archivo.
  • Pantalla completa: botón nativo Fullscreen API.
  • Exportación limpia: descarga <titulo>.svg (con fuentes y variables CSS del tema activo) o <titulo>.png renderizado a 2x. Ninguno incluye el enlace de pie "Made with trazo".
Atajos de Teclado en el Visor
TeclaAcción en el diagrama

- o _Alejar zoom (×0.8 hacia el centro)

Códigos de Error, Warnings Geométricos y Cómo Resolverlos

[DIAGNOSTICS_TABLE]

La parte estable de cada problema en Trazo es severity, code, path y hint (máximo 20 reportes por ejecución). Filtra la matriz para saber exactamente qué acción tomar:

Código Severidad Significado Acción recomendada
geometry/text-overflow WARNING La etiqueta de un nodo es más ancha que su caja. Acorta el texto de label y mueve el detalle largo al campo note.
geometry/label-overlap WARNING Una etiqueta de arista se solapa con un nodo o con otra etiqueta. Acorta las etiquetas de las flechas o reduce densidad en esa zona.
geometry/edge-through-node WARNING Una arista cruza por encima de otro nodo intermedio. Cambia direction (right ↔ down), agrupa nodos relacionados o divide el diagrama.
geometry/node-overlap WARNING Dos cajas de nodos se superponen geométricamente. Agrupa nodos relacionados o divide el diagrama en sub-vistas.
geometry/outside-canvas WARNING Un nodo, grupo o etiqueta quedó fuera del lienzo calculado. NO lo persigas: es un defecto interno de Trazo. Repórtalo como issue en GitHub.
geometry/outside-group WARNING Un nodo quedó dibujado fuera de los límites de su grupo padre. NO lo persigas: es un defecto interno de Trazo. Repórtalo en GitHub.
json/syntax ERROR El archivo no es JSON válido (comas finales, comillas, etc.). Revisa línea y columna reportadas. En Windows PS 5.1, asegúrate de usar Trazo >= 0.1.1 (UTF-16 BOM).
schema/type ERROR Un campo recibió un tipo incorrecto (ej. over en notas). Consulta trazo schema <type> y corrige el tipo en la ruta indicada.
edge/syntax / edge/arrow ERROR Formato o flecha inválida en una arista/mensaje abreviado. Usa únicamente -> (sync), ~> (async) o --> (reply solo en sequence).
ref/duplicate-id ERROR Dos nodos, grupos, pasos, tablas o participantes comparten id. Renombra el duplicado usando el hint first used at ....
ref/unknown-node / -step / -table / -participant ERROR Una arista, grupo, FK o mensaje apunta a un id que no existe. Aplica la sugerencia automática "did you mean ..." o declara el elemento faltante.
column/fk-target ERROR La clave foránea en ERD no tiene formato tabla.columna. Escribe el destino exacto como "tabla.columna" (no se soportan llaves compuestas).

Limitaciones Explícitas (Lo que NO hace)
  • Solo 4 tipos: no cubre Gantt, mapas mentales, C4 completos, diagramas de clases UML ni gráficas estadísticas (para eso usa Mermaid, PlantUML o D2).
  • Sin render inline en Markdown: GitHub/GitLab no renderizan JSON de Trazo directamente dentro de un README.md; debes abrir el .html o exportar a SVG/PNG e incrustar la imagen.
  • Sin edición visual en el HTML: el visor es de solo lectura/exploración. Para cambiar algo, edita el .json y vuelve a ejecutar trazo make.
  • Sin importador de Mermaid ni íconos de marca: no incluye logos de AWS/GCP/Azure ni páginas explicativas interactivas adicionales.
  • Sin llaves foráneas compuestas en ERD: cada fk referencia una sola columna destino.
  • Sin verificación visual en navegador: valida geometría algorítmicamente en Node, sin levantar Playwright/Chrome.
